# Как включить русский язык на Google-Assistant колонке (Xiaomi Mi Smart Speaker L09G) — с нуля

Проверено на **Xiaomi Mi Smart Speaker L09G** (лицензированная колонка с Google Assistant), лето 2026. Метод применим к любой колонке этого класса (Google/Nest/партнёрские), если её прошивка поддерживает русский (см. проверку в §1).

**Не нужны:** MITM-прокси, эмулятор, кастомная прошивка, патч приложения, root на самой колонке. Всё делается штатными средствами + один запрос к локальному API колонки.

---

## Ключевой факт, который всё меняет

Прошивка L09G **сама умеет русский** — просто приложение Google Home не даёт его выбрать. Проверяется одним запросом к колонке (§1). Поэтому задача сводится к тому, чтобы протолкнуть `ru` мимо ограничения приложения. Есть два пути:

- **Путь B (простой, рекомендуется)** — выставить язык Google-ассистента = русский на уровне **аккаунта**; тогда колонки наследуют русский автоматически при привязке.
- **Путь A (запасной)** — если колонка уже застряла на английском: записать `locale=ru` напрямую в колонку через её локальный API (нужен device-токен).

---

## 0. Предусловия

- Колонка Google Assistant (здесь — Xiaomi L09G), включается/сбрасывается штатно.
- Телефон с приложением **Google Home**, в одной Wi-Fi с колонкой.
- Google-аккаунт, к которому привязываете колонку.
- **Для Пути A дополнительно:** рутованный Android-телефон с `adb` (чтобы дотянуться до локального API колонки), компьютер с Python 3, пакеты `glocaltokens` + `gpsoauth`.

---

## 1. Проверка: умеет ли ваша колонка русский (30 секунд)

Узнайте локальный IP колонки (в приложении Google Home → настройки устройства → информация, либо сканом сети) и запросите её список локалей:

```bash
curl -sk 'https://<IP-колонки>:8443/setup/supported_locales' | grep -i '"ru"'
```

Если в ответе есть `{"display_string":"Russian - русский","locale":"ru"}` — прошивка русский умеет, продолжайте. (На L09G — 59 локалей, русский в списке.)

---

## 2. Путь B — русский через язык ассистента аккаунта (простой)

Подходит для новой/сброшенной колонки.

1. Убедитесь, что в **язык Google-ассистента для аккаунта** добавлен русский. Проверить/выставить можно заранее в приложении Google (Ассистент → Настройки → Языки), либо прямо в мастере привязки (шаг 3).
2. Привяжите колонку в Google Home под нужным аккаунтом. Комната, имя — любые.
3. На экране языка **устройства** русского не будет — выберите English (US), продолжайте.
4. Если всплывёт экран **«язык голосового помощника»** (это уже уровень аккаунта) с отмеченным **«Русский (Россия)»** — оставьте русскую галочку, English НЕ отмечайте, жмите «Далее».
5. Колонка поднимется на русском.

> В конце мастер может показать ложное **«Не удалось настроить устройство»** — это косметический баг, устройство реально работает и появляется в списке. Игнорируйте.

Если колонка всё же встала на английском — переходите к Пути A.

---

## 3. Путь A — прямая запись `locale=ru` в колонку (запасной)

Нужен, когда устройство застряло на английском. Пишем локаль прямо в колонку через её локальный API. На запись API требует device-токен `cast-local-authorization-token` (LAT) — без него `HTTP 401`.

### 3.1. Получить device-LAT

LAT добывается из Google-аккаунта, которому принадлежит колонка.

**a) master-token аккаунта.** App-password + `perform_master_login` **не работает** (Google отдаёт `BadAuthentication`). Рабочий путь — браузерный `oauth_token`:
- Приватное окно браузера → `https://accounts.google.com/EmbeddedSetup` → войдите под аккаунтом.
- На странице условий (НЕ нажимая «Принять») → DevTools (F12) → Application → Cookies → `accounts.google.com` → скопируйте cookie **`oauth_token`** (начинается с `oauth2_4/…`; одноразовый, живёт минуты).
- Обменяйте на master-token:
  ```python
  import gpsoauth
  r = gpsoauth.exchange_token("<email>", "<oauth_token>", "3d5edf8f2b0e9a11")
  master = r["Token"]   # aas_et/… — СОХРАНИТЕ СРАЗУ, он долгоживущий и переиспользуемый
  ```

**b) LAT из homegraph** (обходя баг glocaltokens, который игнорирует переданный master-token):
```python
from datetime import datetime
import gpsoauth
from glocaltokens.client import GLocalAuthenticationTokens
email="<email>"; aid="3d5edf8f2b0e9a11"
at = gpsoauth.perform_oauth(email, master, aid,
        service="oauth2:https://www.google.com/accounts/OAuthLogin",
        app="com.google.android.apps.chromecast.app",
        client_sig="24bb24c05e47e0aefa68a58a766179d9b613a600")["Auth"]
g = GLocalAuthenticationTokens(master_token=master, username=email, android_id=aid)
g.access_token = at; g.access_token_date = datetime.now()
for d in g.get_homegraph().home.devices:
    if d.local_auth_token and d.hardware.model == "Mi Smart Speaker":
        print(d.device_name, d.local_auth_token)   # это и есть LAT (~108 симв)
```

### 3.2. Записать локаль в колонку

С устройства, которое **видит колонку локально** (обычно телефон через `adb`, т.к. ПК по Wi-Fi может её не видеть):

```bash
curl -sk -X POST 'https://<IP-колонки>:8443/setup/set_eureka_info' \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://www.google.com' \
  -H "cast-local-authorization-token: <LAT>" \
  --data '{"settings":{"locale":"ru"}}'
```

**Критично:**
- Тело — именно `{"settings":{"locale":"ru"}}` (локаль вложена в `settings`). Плоский `{"locale":"ru"}` вернёт `200`, но будет **молча проигнорирован**.
- Значение — `ru` (не `ru-RU`).
- Ответ должен быть `HTTP 200`. Проверка: `GET /setup/eureka_info?options=detail` → поле `"locale":"ru"`.

### 3.3. Проверка

Спросите колонку голосом что-нибудь по-русски. Локаль переживает перезагрузку колонки (проверено). **Factory reset её стирает** — после сброса повторить.

---

## 4. Частые проблемы

- **«Не удалось настроить устройство»** в конце мастера — ложная ошибка, устройство работает. Проверьте список устройств.
- **«Устройство настроено, но не найдено»** — не проксируйте локальное подключение к колонке (если ставили прокси/MITM для чего-то — исключите IP колонки; проще снять прокси на время привязки). ПК на ethernet может не видеть колонку на Wi-Fi — это нормально, работайте с телефона.
- **`HTTP 401` при записи** — нет/неверный LAT. Перевыпустите (§3.1). LAT живёт ограниченно.
- **Master-token протух** — повторите браузерный `oauth_token` (§3.1a).

---

## 5. Безопасность

- **Master-token = полный доступ к аккаунту.** Храните обдуманно (файл с правами `600`, не в публичных репозиториях/облаках). При компрометации — выйдите из всех сессий (myaccount.google.com → Security → ваши устройства → Sign out), это инвалидирует токен.
- App-password, если создавали для попыток, — отзовите (он для этого флоу всё равно не работает).
- LAT — device-scoped, короткоживущий; отдельно хранить смысла нет, перевыпускается из master-token.
