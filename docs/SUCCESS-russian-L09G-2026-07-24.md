# ✅ РЕШЕНО: русский язык на Xiaomi Mi Smart Speaker L09G (2026-07-24)

После многосессионной саги колонка **заговорила по-русски**. Рабочий способ — прямая запись локали в устройство через его локальный API с валидным device-токеном (LAT). Ни MITM, ни эмулятор, ни прошивка, ни патч приложения **не понадобились**.

## Ключевое открытие, которое всё решило

Прошивка L09G **сама поддерживает русский** — `GET https://<ip>:8443/setup/supported_locales` возвращает 59 локалей, включая `{"locale":"ru","display_string":"Russian - русский"}`. Все прошлые сессии ошибочно считали устройство блокером. Реальный барьер был только в том, что приложение Google Home не даёт выбрать `ru`, а прямая запись в устройство требует авторизации.

## Рабочий рецепт (то, что реально сработало)

### Предусловия
- Колонка привязана к аккаунту и в сети (у нас `.169`, `model=Mi Smart Speaker`, изначально `locale=en-US`).
- Рутованный Android-телефон в той же Wi-Fi с `adb` (нужен, чтобы (а) достучаться до локального API колонки — Mac по Wi-Fi её не видит; (б) при желании читать данные аккаунта). Строго говоря, для записи достаточно ЛЮБОГО хоста в той же сети, что видит колонку, + LAT.
- Python на Mac с `glocaltokens` + `gpsoauth` (venv).

### Шаг 1. Получить device-LAT (`cast-local-authorization-token`)
LAT добывается из Google-аккаунта, владеющего колонкой (`4923920@gmail.com`):

1. **Master-token аккаунта.** App-password + `gpsoauth.perform_master_login` **НЕ работает** (Google отдаёт `BadAuthentication` — флоу отключён ~2023+). Рабочий путь — браузерный `oauth_token`:
   - Приватное окно → `https://accounts.google.com/EmbeddedSetup` → войти под аккаунтом.
   - На странице условий (НЕ нажимая «Принять») → DevTools → Application → Cookies → `accounts.google.com` → скопировать cookie **`oauth_token`** (`oauth2_4/…`, одноразовый, живёт минуты).
   - `gpsoauth.exchange_token(email, oauth_token, android_id)` → `Token` = master-token (`aas_et/…`, ~223 симв). **Master-token долгоживущий — сохранить сразу.**
2. **Access-token** (обходя баг glocaltokens, который игнорирует переданный master_token):
   ```python
   res = gpsoauth.perform_oauth(email, master_token, android_id,
       service="oauth2:https://www.google.com/accounts/OAuthLogin",
       app="com.google.android.apps.chromecast.app",
       client_sig="24bb24c05e47e0aefa68a58a766179d9b613a600")
   access_token = res["Auth"]
   ```
3. **LAT из homegraph:**
   ```python
   g = GLocalAuthenticationTokens(master_token=master_token, username=email, android_id=android_id)
   g.access_token = access_token
   g.access_token_date = datetime.now()          # чтобы не лез за master повторно
   hg = g.get_homegraph()
   for item in hg.home.devices:                   # путь именно .home.devices
       if item.local_auth_token and item.hardware.model == "Mi Smart Speaker":
           lat = item.local_auth_token            # ~108 симв — это и есть LAT
   ```
   (`android_id` — любой стабильный 16-hex, у нас `3d5edf8f2b0e9a11`; важно использовать один и тот же во всех вызовах.)

### Шаг 2. Записать локаль в колонку (ГЛАВНОЕ — формат тела)
`POST https://<ip>:8443/setup/set_eureka_info` с телефона (он видит колонку локально):
```
curl -sk -X POST 'https://192.168.1.169:8443/setup/set_eureka_info' \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://www.google.com' \
  -H "cast-local-authorization-token: <LAT>" \
  --data '{"settings":{"locale":"ru"}}'
```
- **Критично:** тело — `{"settings":{"locale":"ru"}}` (locale вложен в `settings`). Плоский `{"locale":"ru"}` возвращает **HTTP 200, но молча игнорируется** — локаль не меняется. Вложенный формат применяется.
- Без заголовка LAT — **HTTP 401**. С валидным LAT — **200 и локаль меняется**.
- Значение — `ru` (bare code из supported_locales), не `ru-RU`.

### Шаг 3. Проверка
`GET /setup/eureka_info?options=detail` → поле `"locale": "ru"`. Голосом: «Окей, Google, который час?» → отвечает по-русски. **Подтверждено вживую.**

## ⭐ Более простой путь для ДОПОЛНИТЕЛЬНЫХ колонок (открыт 2026-07-25)

После того как язык ассистента аккаунта выставлен на **русский** (облачный слой), новые колонки этого же аккаунта **наследуют русский автоматически** при привязке — локальная запись `set_eureka_info` не нужна.

Как это происходит на практике (проверено на 2-й колонке):
1. Привязываешь новую колонку в Google Home под тем же аккаунтом `4923920@gmail.com`.
2. В мастере всплывает экран **«язык голосового помощника»** с уже отмеченным **«Русский (Россия)»** (English НЕ отмечен). Оставляешь русскую галочку, English не трогаешь, жмёшь «Далее».
3. Колонка поднимается сразу на русском. (Мастер в конце покажет ложное «не удалось настроить устройство» — косметический баг, устройство реально работает.)

Итог — два рабочих пути:
- **Путь A (эта колонка №1, «в лоб»):** локальная запись `set_eureka_info {"settings":{"locale":"ru"}}` + LAT. Нужен, когда устройство застряло на английском и экран языка ассистента не даёт русский. Инструмент: `tools/russify-speaker.sh <ip>`.
- **Путь B (колонка №2, проще):** язык ассистента аккаунта = русский → новые устройства наследуют его сами при setup. Ничего локально писать не надо.

`tools/russify-speaker.sh` остаётся как **фоллбэк** — если какая-то колонка всё же встанет на английском.

## Что осталось проверить / открытые вопросы

- **Персистентность — ПОДТВЕРЖДЕНА.** Русский **пережил ребут колонки** (`POST /setup/reboot` с LAT → после перезагрузки `locale=ru`, отвечает по-русски). Это опровергает исторический паттерн «русский один раз → откат»: прямая запись device-слоя держится через power-cycle. Осталось лишь бытовое наблюдение за облачной ресинхронизацией на длинной дистанции (день+), но device-локаль стабильна. Метод считается надёжным.
- **Factory reset колонки стирает это** (locale вернётся к дефолту) — после любого сброса рецепт нужно повторить (LAT можно переиспользовать, если master-token сохранён; иначе — заново браузерный oauth_token).
- **OTA прошивки** — вероятно, не откатывает (device-локаль в конфиге, не в прошивке), но не проверено.

## Секреты (НЕ в этом файле)
- Master-token лежал в session-scratchpad (`master.txt`, права 600) — **это временная папка сессии, удалится**. Для повторного применения после будущих сбросов master-token нужно сохранить в надёжном месте (он = полный доступ к аккаунту; хранить обдуманно) ИЛИ каждый раз заново брать браузерный `oauth_token`.
- App-password, который засветился в чате, **отозвать** на myaccount.google.com/apppasswords (через master-login он всё равно не работал).
- LAT (`lat_0.txt`) — device-scoped, живёт ограниченно; при необходимости перевыпускается из master-token (Шаг 1.3).
